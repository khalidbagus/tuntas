**Observed.** Signed-out Work browser showed project, frames, style tile, agent panel, and rendered Create Action form. The panel describes a linked journey; that description is not proof of working transitions. Export inspection covered 36 distinct HTML screens, 33 PNGs and DESIGN.md; the nested export repeats the same file contents. The three HTML-only frames are Library 2, Details 2 and Create Action. No separate runnable app, Git checkout, backend, or prototype URL in the package. These are standalone Tailwind-driven HTML documents with inline scripts, remote assets, placeholder navigation and fixed example data. Some controls change local presentation; no demonstrated durable cross-screen capture flow. No end-to-end live Stitch playback verified. Source notes are design evidence, not authorization to implement payment, alerts or sharing.

**First-use critique.** Capture is discoverable, but scan, confirm, process, review and success can become five pages for one receipt. The Library can visually identify an old receipt, but its example counts, search chips and anchor targets do not retrieve a newly captured record. Reclassify is visible on Details 2; a persistent correction is unproven. The narrow screenshots have many tiny metadata chips and some icon-only buttons. Keep a text label, 44px targets, keyboard focus and live feedback. Use the desktop width for navigation, working area and supporting content, not stretched mobile panels.

**Selected tokens:** use DESIGN.md's narrative white, #F7F9FC, #E5EAF2, #17243B and #2F66F6; its YAML uses a bluer surface and #004CD8 primary, useful for darker interactions. Space Grotesk headings, Plus Jakarta Sans body. Use 8/16/24/32px spacing, 12–16px corners. Restrict green to status. Use compact document rows, icon tiles, a file drop target, labeled inputs, single primary button and text status. Decorative paper artwork must be synthetic.

**Interaction evidence.** In isolated Chromium with external assets blocked, clicking Library on the capture-first Home export left the Home heading in place (anchor target `#`). Confirming Create Action changed the button and showed a fixed December 2024 toast; it did not open an Actions list. The Home export also disables user zoom. The implementation preserves zoom and replaces these stand-ins with storage-backed routes. See the [per-screen file, dimensions, controls and anchor register](EXPORT-REGISTER.md).

**Priorities.** P0: capture + preserve original, bounded extraction, conditional review, search/detail/correction, explicit action, duplicate/error/undo, safe processing modes. The remaining P0 competition gate is to prove Firebase device and consented fallback on an authorized test project. P1: multi-device backup only with an account, isolation rules and explicit storage consent; batch intake and cold-start offline. P2: graph evidence, optional linked documents, extra Home variants.

**Proposed routes and interaction contract:** Home → Capture (file/camera/text) → pending → local save → processing → organized → Library → document → create action → Actions → complete/reopen/source. Uncertain → Inbox → correct → Library. Error → retry with explicit mode, or file manually. Duplicate → existing original. Undo → Inbox. Use actual download/upload language only where bytes leave the device. All routes must be reachable without a welcome wizard. The local guest workspace belongs to this browser profile, not to a signed-in identity.
